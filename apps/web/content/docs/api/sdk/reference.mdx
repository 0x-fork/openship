This reference lists the current 25 operation groups on both `OpenshipClient` and native `ScopedShip`.
Use `client.projects.get(id)` remotely or `scope.projects.get(id)` natively. The same public operation
interfaces describe both. See [release availability](/docs/api/sdk#install) before installing.

The tables show argument order; `?` means optional. Input and result types come from the public TypeScript
interfaces named in each section. A method returning a promise is awaited; an async iterable is consumed
with `for await`. Existing HTTP module references provide the underlying field descriptions. SDK methods
project the HTTP envelopes into the result declared by their operation type.

## Workflows and types

The client and native scope also expose `deploy(input)` and `deployment(id)`. The native installation
provides `scope({ identity, organizationId })`; the remote client provides `scope(organizationId)`.
See [deployment workflows](/docs/api/sdk/deployments) and [native lifecycle](/docs/api/sdk/native).

Import operation interfaces and DTOs from the public package. You can derive a method's exact input or
result type without maintaining another schema:

```ts title="operation-types.mts"
import type { ProjectOperations, DeploymentOperations } from "openship";

export type ProjectUpdate = Parameters<ProjectOperations["update"]>[1];
export type ProjectPage = Awaited<ReturnType<ProjectOperations["list"]>>;
export type DeploymentSubmission = Awaited<ReturnType<DeploymentOperations["create"]>>;
```

Shared helpers exported from `openship` include `iteratePages`, `createDeploymentHandle`,
`waitForDeployment`, `consumeDeploymentEvents`, and `normalizeComposeServices`. `openship/client` also
exposes `HttpClient` and `parseSSE` for transport integrations. Prefer the named operations for their
validated inputs and result types.

## Availability

An exposed method is not a guarantee that every deployment mode can execute it. User grants, credential
restrictions, provider configuration, installation authority, host policy, and API version still apply.
Unsupported capabilities fail explicitly.

| Area                      | Current boundary                                                                                                                                             |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Native and remote clients | Share the groups below; remote calls require compatible server routes.                                                                                       |
| Cloud                     | Use the canonical Cloud API and its organization ID. Verified local-to-Cloud tenant mapping and promotion/reconciliation remain incomplete.                  |
| Jobs, backups, and scans  | Native scheduling is opt-in. Constrained saved principals and distributed scheduler ownership remain migration work.                                         |
| System and accounts       | Existing methods are listed below; setup/onboarding, self-app management, complete edge/terminal support, and organization/account lifecycle are incomplete. |
| Mail and data transfer    | No complete named SDK groups yet. An existing HTTP endpoint may be called through the remote client's transport.                                             |
| Delivery and replay       | Durable distributed dispatch, idempotency, event replay, and complete billing webhook replay/accounting guarantees remain unfinished.                        |

Browser authentication redirects, cookies, provider webhook signature verification, and interactive
terminal handshakes remain transport-specific boundaries. SDK imports do not replace those protocols.

## Installation operator

The operator is separate from the 25 ordinary operation groups. Native hosts must enable
`administration: true`; an ordinary scope never includes the operator. Remote operator access uses
`OpenshipOperatorClient` with an explicit internal token.

| Capability                             | Native operator | Remote operator |
| -------------------------------------- | --------------- | --------------- |
| `ensureIdentity(input)`                | Yes             | Not exposed     |
| `resolveIdentity({ issuer, subject })` | Yes             | Not exposed     |
| `ensureNamespace(input)`               | Yes             | Not exposed     |
| `setMembership(input)`                 | Yes             | Not exposed     |
| `notices.listAll()`                    | Yes             | Yes             |
| `notices.create(input)`                | Yes             | Yes             |
| `notices.remove(id)`                   | Yes             | Yes             |

See [native provisioning](/docs/api/sdk/native#users-namespaces-and-membership) and
[remote operator configuration](/docs/api/sdk/client#installation-operator).
